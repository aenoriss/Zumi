# Agent skills for building and maintaining the Zumi design system — 2026-10-15

Research date: 2026-10-15. Primary sources only: the SKILL.md / README of each candidate (raw.githubusercontent.com), GitHub API for stars / last push / licence (`gh api repos/...`, read 2026-10-15), npm registry for versions, and official tool docs (Style Dictionary, Storybook, Tokens Studio, shadcn, Penpot, Unity Manual). Where a SKILL.md could not be read, that is flagged and the entry rests on the README or a search snippet. Requirements: drive (1) token definition in a shared `packages/design-tokens` (JSON → CSS variables → Unity C#), (2) component inventory + Storybook in `packages/ui` (Next.js), (3) a11y, (4) dark/light theming, (5) documentation + consistency enforcement, (6) multi-platform export (Style Dictionary / Tokens Studio / W3C DTCG).

## Executive summary

1. **No single skill covers the whole brief.** Of 14 candidates read, none combines DTCG tokens + Style Dictionary build + Storybook stories + a11y + theming + a non-web export. The two that come closest are packs, not single skills: `dylantarre/design-system-skills` (27 skills: OKLCH colour/space/type scales, 3-layer token structure, `style-dictionary`, `storybook`, `dark-mode`, `color-contrast`, `aria-patterns`, `token-docs`) and `Tyler-R-Kendrick/agent-skills` `design-system/` (4 tightly scoped, cross-referencing skills: `design-tokens` (DTCG), `style-dictionary` (v4, `registerFormat`), `storybook` (CSF3, `addon-a11y`, play tests), `figma`).
2. **Evidence is thin everywhere.** Star counts of the design-system-specific repos: 586 (designer-skills), 276 (Mindrally pack), 244 (extract-design-system), 50 (dylantarre), 15 (ilikescience), 12 (Tyler-R-Kendrick), 3 (gregorymm), 0 (SkillMedev). Only `ilikescience/design-tokens-skill` ships an `evaluations/` folder. The high-star skills on skills.sh (`anthropics/skills frontend-design` 988K installs, `Leonxlnx/taste-skill` 96.6K stars, `pbakaus/impeccable` 81.3K stars) are aesthetic-direction skills and do **not** cover tokens/Storybook/export.
3. **Tooling has moved faster than the skills.** Style Dictionary is at **v5.6.1** (2026-10-10); every skill read targets v4 (Tyler-R-Kendrick) or v3-style CommonJS (dylantarre). Storybook is at **10.6.2** (2026-10-12) with `@storybook/nextjs-vite` as the recommended Next.js framework and a first-party `@storybook/addon-mcp` 10.6.2; every Storybook skill read assumes 7/8-era packages (`@storybook/test`, `@storybook/blocks`). W3C DTCG shipped its first stable spec **2025.10** (2025-10-28); Style Dictionary says full 2025.10 support is "in progress for v5". Penpot and Tokens Studio both import/export DTCG JSON natively.
4. **No skill exports tokens to C# or USS.** GitHub code search for Style Dictionary + C# formats returns 0 hits; Style Dictionary's built-in formats stop at Swift/Android XML/Compose/Flutter. The only Unity theming skill found is `app-ui-theming` inside Unity's App UI package (`com.unity.dt.app-ui`): it documents hand-written USS variable layers (palette → alias → theme → scale, `--appui-*`) and `.tss` files, with no JSON pipeline. Unity's official plugin `ui-uitk` skill has no token guidance. **The JSON→C#/USS exporter must be written by us** (a Style Dictionary `registerFormat` of ~50 lines plus a Zumi SKILL.md).
5. **Recommendation:** install `Tyler-R-Kendrick/agent-skills` `design-system/*` (DTCG + SD v4 + Storybook CSF3/a11y, MIT, correct spec vocabulary) as the token/story backbone; add `dylantarre/design-system-skills` only for its scale generators, `dark-mode`, `color-contrast`, `aria-patterns` (MIT; v3-era examples, last push 2025-12-30 — treat as reference, not authority); keep `anthropics/skills frontend-design` for the brand pass after the grill. Write one Zumi skill (`zumi-design-system`) that pins SD v5 / Storybook 10.6 / `nextjs-vite`, encodes the comic-native brand rules, and owns the `csharp/scriptable-object` + `uss/variables` formats.
6. Uncertainties: three SKILL.md files were unreadable (mindrally `storybook`, pedronauck `storybook-stories` read via the `mine/` path only, Storybook's own `@storybook/claude-code-plugin` skills — repo archived, moved into `storybookjs/storybook`); skills.sh shows install counts only for the top ~278 entries, so niche skills' adoption is unknown; licences for `pedronauck/skills` and `anthropics/skills` (per-skill LICENSE.txt) are not stated at repo level.

## B. Per-candidate notes

**1. Tyler-R-Kendrick/agent-skills — `design-system/`** (https://github.com/Tyler-R-Kendrick/agent-skills/tree/main/skills/design-system). Four skills with explicit scope boundaries that route to each other (tokens → `design-tokens`, build → `style-dictionary`, docs → `storybook`, handoff → `figma`). `design-tokens` (~1,000 words): DTCG `$value/$type/$description/$deprecated/$extensions`, 7 primitive + 5 composite types, group `$type` inheritance, `{alias}` and JSON-Pointer refs, 3-tier global/semantic/component, themes override only the semantic layer. `style-dictionary`: pins v4+, `outputReferences: true` for runtime theming, one config per theme, `registerTransform`/`registerFormat` examples, CI build. `storybook`: CSF3 default "since Storybook 7", CSF Factories marked experimental, `@storybook/addon-a11y` on by default, play functions with `@storybook/test`, `test-storybook` in CI. Gaps: no C#; `@storybook/test` is the 8.x package name (Storybook 9+ uses `storybook/test`); 12 stars, one author, design-system dir last touched 2026-02-11 (`gh api .../commits?path=skills/design-system`). Best vocabulary match for Zumi's `packages/design-tokens` → `packages/ui` split.

**2. dylantarre/design-system-skills** (https://github.com/dylantarre/design-system-skills). Broadest pack: `tokens/` (color-scale OKLCH, spacing/type/shadow/radius/motion/z-index scales, `design-tokens-structure`, responsive-typography), `tools/` (style-dictionary, storybook, figma, framer), `accessibility/` (color-contrast, focus-states, aria-patterns), `patterns/` (dark-mode, compound-components Radix/Headless UI, icon-system, layout-primitives), `documentation/` (token-docs, component-docs). `design-tokens-structure` uses a custom `{ "value": ... }` JSON, **not DTCG**; dark mode = `semantic/dark.json` + `[data-theme="dark"]`. `style-dictionary` SKILL.md is long and practical (multi-theme configs, GitHub Actions, troubleshooting) but mostly v3 CommonJS with a v4 ESM aside; no C#. `storybook` SKILL.md: `.storybook/main.ts|preview.ts`, theme toolbar global + `data-theme` decorator, MDX token pages with `ColorPalette`, `addon-a11y` per-story rules — 7/8-era packages. No evals; 50 stars; last push 2025-12-30 (9.5 months). Useful as recipes, not as an authority on current versions.

**3. ilikescience/design-tokens-skill** (https://github.com/ilikescience/design-tokens-skill). Deepest DTCG skill: structured colour (`colorSpace`/`components`/`alpha`/`hex`, OKLCH etc.), resolvers (`sets`, `modifiers`, `resolutionOrder`) recommended over group extension for light/dark/high-contrast, validation rules, Figma-export import, `reference/`, `fixtures/` (primitives, semantic, resolver.json, themes/) and an `evaluations/` folder — the only candidate with evals. Tooling is **Terrazzo**, Style Dictionary appears only as a `terrazzo convert --from style-dictionary` source. 15 stars, push 2026-06-17, licence not stated in README (uncertain).

**4. Mindrally/skills `design-systems`** (https://www.skills.sh/mindrally/skills/design-systems). Checklist-style 7-step workflow (audit → tokens → foundations → patterns → Storybook → governance/Chromatic/axe → ship). Good as a process spine; weak on specifics: no DTCG, no theming mechanism, Button example uses inline styles and references undefined tokens. 884 installs, three security audits listed on skills.sh, pack pushed 2026-10-08.

**5. julianoczkowski/designer-skills** (https://github.com/julianoczkowski/designer-skills). Process pack mirroring Matt Pocock's flow (`/grill-me` → `/design-brief` → `/design-tokens` → `/brief-to-tasks` → `/frontend-design` → `/design-review`), writes to `.design/`. `/design-tokens` inventories existing CSS vars / Tailwind / shadcn themes before generating, derives from a named aesthetic philosophy, always emits light + dark, `prefers-color-scheme` + `[data-theme="dark"]`. Output is CSS vars / `tailwind.config.js` / `theme.ts` — no JSON source of truth, no contrast audit. Overlaps with the existing `grilling`/`frontend-design` skills already installed here.

**6. SkillMedev/design-system-builder** — 0 stars, half the skills are "external" links to a skillme.dev catalogue; skip (https://github.com/SkillMedev/design-system-builder).

**7. gregorymm/design-tokens** — Figma-only ingestion (Desktop MCP or REST PAT; write-back needs Enterprise or a generated plugin), emits DTCG or CTI + `style-dictionary.config.json`. Relevant only if Zumi designs in Figma; Penpot users get DTCG export natively (§C). 3 stars (https://github.com/gregorymm/design-tokens).

**8. arvindrk/extract-design-system** — Playwright scrape of a public site → `design-system/tokens.json` + `tokens.css`; schema not stated (DTCG unconfirmed). Useful once, for benchmarking competitor comic sites, not for maintenance (https://github.com/arvindrk/extract-design-system).

**9. shadcn/ui skill** — strongly opinionated (Tailwind v4 `@theme inline`, Radix, `components.json`, registries `@shadcn`, `owner/repo/item`). Its `design-system.md` maps a DESIGN.md onto shadcn CSS variables. Only worth installing if the grill lands on shadcn as the `packages/ui` base; comic-native ink outlines/bubbles argue against a shadcn look (https://raw.githubusercontent.com/shadcn/ui/main/skills/shadcn/SKILL.md).

**10–12. frontend-design / impeccable / taste-skill** — aesthetic direction, anti-"AI slop" rules, browser self-review (taste-skill: 3 widths, up to 3 rounds; impeccable: 59 deterministic detectors, `audit`, `extract` → `.impeccable/design.json`). None defines a token format, Storybook, or export. `frontend-design` is already installed here.

**13. pedronauck storybook-stories** — convention-following skill ("extend nearest story, reuse global QueryClient/router/MSW decorators, smallest state set") with `references/patterns.md`. No version, no a11y addon. Good as a *maintenance* skill once Storybook exists (https://raw.githubusercontent.com/pedronauck/skills/main/skills/mine/storybook-stories/SKILL.md).

**14. Unity** — Official plugin (29 skills, released 2026-09-09, Unity Companion License, `gh`: 417 stars, pushed 2026-10-09): `ui-uitk` lists unsupported USS (`gap`, `z-index`, `box-shadow`, `:nth-child`…), bans inline styles, says tokens must keep contrast — but no `var()`/TSS/token guidance (https://raw.githubusercontent.com/Unity-Technologies/unity-agent-plugin/main/skills/ui-uitk/SKILL.md). App UI's `app-ui-theming` (https://raw.githubusercontent.com/needle-mirror/com.unity.dt.app-ui/master/Plugins~/skills/app-ui-theming/SKILL.md) is the only USS-variable theming skill found: palette → alias → theme (`.appui--<name>`) → scale layers, `--appui-primary-25…1300`, `--appui-spacing-50…800`, `ThemeContext`/`ScaleContext` runtime switching, `.tss` assigned in PanelSettings. No JSON→USS generation. GitHub code search `"USS" "design tokens" filename:SKILL.md` → 121 hits, none a token pipeline.

## E. Recommendation

Ranked by fit → maintenance → evidence.

1. **Backbone: Tyler-R-Kendrick `design-system/*`** — `npx skills add Tyler-R-Kendrick/agent-skills --skill design-tokens`, then `--skill style-dictionary`, `--skill storybook`. Covers DTCG authoring (3-tier, theme-dark overrides semantic only), SD build with `outputReferences`, CSF3 stories with `addon-a11y` + play tests. MIT. Risk: 12 stars, single author, v4/Storybook-8 package names — our wrapper skill overrides versions.
2. **Reference recipes: dylantarre `design-system-skills`** — `npx skills add dylantarre/design-system-skills`; use `color-scale` (OKLCH), `spacing-scale`, `type-scale`, `dark-mode`, `color-contrast`, `focus-states`, `aria-patterns`, `token-docs`. Ignore its non-DTCG token JSON and v3 SD config. MIT. Risk: unmaintained since 2025-12-30.
3. **Brand pass (already installed): `frontend-design`** after the grill; optionally `ilikescience/design-tokens-skill` if resolvers/multi-dimensional themes (light × dark × high-contrast × XR) become necessary — it is the only one with evals.

Skip: SkillMedev (0 stars, external links), gregorymm (Figma-only), Mindrally (too generic), shadcn skill (unless the grill picks shadcn), taste-skill/impeccable (aesthetics only; impeccable's detector `audit` could be a CI lint later).

**Gap we write ourselves — `zumi-design-system` SKILL.md** (project-level `.claude/skills/`): (a) pins **Style Dictionary 5.6.x**, **Storybook 10.6.x** with `@storybook/nextjs-vite`, `storybook/test` imports, `@storybook/addon-a11y`, `@storybook/addon-mcp`; (b) encodes the comic-native brand decisions from the grill (ink stroke width tokens, bubble radius/tail tokens, halftone/texture tokens, type roles for lettering vs UI); (c) defines the `packages/design-tokens` layout (`primitives.tokens.json`, `semantic.tokens.json`, `themes/light|dark`) and build targets: `css/variables` → `packages/ui`, custom `uss/variables` (resolved values, one `.uss` per theme + Zumi `.tss` importing `unity-theme://default`) and custom `csharp/scriptable-object` (`ZumiTokens.cs` partial class + `.asset` or a generated static class) → `unity/Assets/Zumi/DesignTokens/`; (d) consistency rules: no raw hex outside primitives, every component story has light + dark + a11y pass, token diff must rebuild all three platforms in CI. Estimated size: ~150 lines of SKILL.md + ~80 lines of `registerFormat` JS; nothing comparable exists to install.
