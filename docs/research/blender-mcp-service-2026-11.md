## Summary

1. **The prior note's rule "no add-on socket under `-b`" is true for ahujasid and false for the Blender Lab add-on.** The Lab add-on ships `blender --background file.blend --command blender_mcp [--host --port]`, a `select()`-based blocking loop written "for use in `blender --background` mode where `bpy.app.timers` do not fire" (`addon/blender_mcp_addon/cli.py`, `execute_blocking.py`) **[src]**. `render_viewport_to_path` runs synchronously there (`use_deferred = not bpy.app.background`); only the screenshot and `jump_to_*` tools return "Screenshots are not available in background mode" **[src]**. So: no Xvfb, no GUI, one Blender process, official and GPL-3, Blender ≥ 5.1 (`blender_version_min = "5.1.0"`) **[src]**.
2. **Rank 1 shape**: a Modal `@app.cls(gpu="L4")` container with Blender 5.2.3 LTS, the Lab add-on in `--background --command blender_mcp`, and a ~150-line agent loop exposing **four plain function tools** (`execute_bpy`, `render`, `inspect`, `export_glb`) to OpenRouter over the add-on's socket; MCP stays out of the hot path. The pipeline calls `job.spawn()` from the Modal client (no HTTP, no 150 s cap) inside `spend.reserve`. Per 8-round job: **~0.03 USD on Claude Haiku 5.5, ~0.22 on Gemini 3.8 Flash, ~0.53 on Sonnet 5.5, plus ~0.05 USD of L4** **[est from live prices]**.
3. **MCP only where it buys something**: Claude Code headless (`claude -p --bare --mcp-config`) as the runtime works through OpenRouter's Anthropic-format endpoint, but is "only guaranteed to work with the Anthropic first-party provider" **[docs]** and its system prompt adds thousands of tokens per turn **[est]**.
4. **Cheapest experiment**: one container, "a candle in a bottle on a wooden coaster", 3 rounds on Haiku 5.5: < 0.05 USD, 2–3 min wall after a one-off image build **[est]**.

## 1. The Blender side

### Blender Lab MCP (installed here)

- Two processes: `blender-mcp` (Python ≥ 3.10, `mcp[cli]>=1.2.0,<2`, lock 1.30.0) speaks MCP over **stdio or Streamable HTTP** (`--transport http --port 9191`) and relays "null-byte-delimited JSON requests" to the add-on's TCP socket (`localhost:9876`, `BLENDER_MCP_HOST/PORT`), timeout 300 s **[src]**. 26 tools: `execute_blender_code`, `get_objects_summary`, `get_object_detail_summary`, `render_viewport_to_path` (`write_still=True`), `render_thumbnail_to_path` (16 samples), screenshots, `jump_to_*`, bundled API/manual search, `get_blendfile_summary_*`, and six `*_for_cli` variants that each spawn `blender --background <file> --python-expr` **[src]**.
- Background mode: the add-on registers `bpy.utils.register_cli_command("blender_mcp", …)`; `cli_execute` starts the socket server and loops `poll_blocking()`; "Deferred responses are not supported in background mode; each request must complete before returning" **[src]**. Deferred (GUI) renders have a 3600 s cap **[src]**. Safety is a "weak sandbox" that blocks `sys.exit` and says "If the LLM (or its user) is motivated these can be worked around" **[src]**; blender.org adds "execute LLM generated code in Blender without any guards … use a virtual machine" **[docs]**. A container is that VM.
- Quirk: `render_thumbnail_to_path` checks `rd.engine == "BLENDER_EEVEE_NEXT"`, but 5.x renamed the id to `BLENDER_EEVEE` (prior note § 5), so its EEVEE sample override is dead on 5.x; Cycles thumbnails are fine **[src, not run]**.
- Install headless: `blender -b -c extension build --source-dir addon/blender_mcp_addon` → `blender -b -c extension install-file mcp-1.0.0.zip --repo=user_default` (the repo's own recipe) **[src]**; enabling the add-on from a `--python-expr` (`addon_enable` + `save_userpref`) is the obvious next line but **[unverified]**.

### ahujasid/mcp-for-blender

Renamed 2026-09-16, 33.6k stars, Blender ≥ 3.0 **[docs]**. The add-on's `start()` prints "cannot start server in background mode (blender -b) - commands would never execute … use a virtual display: xvfb-run -a blender" and returns **[docs]**. It needs a GUI under Xvfb; `get_viewport_screenshot(max_size=800)` draws the `VIEW_3D` area through `gpu.types.GPUOffScreen`, with a `screenshot_area` fallback that "can be all-black when the window is not composited" **[docs]**. Nine server tools (`execute_blender_code`, `look`, `get_scene_info`, `generate_3d`, `search_assets`, `import_asset`, …); socket timeout 180 s; telemetry on by default ("a minimal anonymous usage record"), `DISABLE_TELEMETRY=true` **[docs]**. Its Docker image runs only the MCP server ("Blender still runs on the host") **[docs]**. [BATTLEHAWK00/blender-server-mcp-docker](https://github.com/BATTLEHAWK00/blender-server-mcp-docker) does run Blender 5.2.1 GUI under Xvfb with a vendored ahujasid: Streamable HTTP + Bearer, NVIDIA only (`NVIDIA_DRIVER_CAPABILITIES=compute,utility,graphics`), apt `xvfb libgl1 libegl1 libxkbcommon-x11-0 libxxf86vm1 libxi6 libxrender1 libxfixes3 libglib2.0-0 libgomp1`, "all clients share one scene" **[docs]**. Worth it only for its asset/generative plumbing, which the prior note already recommends calling by HTTP.

### Other options

- **`bpy` wheel**: PyPI today: 4.5.0–4.5.15 are cp311, manylinux_2_28 ≈ 373 MB; 5.2.3 is `==3.13.*` **[docs]**. Modal's example (`debian_slim("3.11") + apt xorg libxkbcommon0 + bpy==4.5.0`, L40S) reports "about six seconds" per frame **[docs]**. In-process is simplest, but LLM code that segfaults bpy kills the agent too **[est]**.
- **mcpBlender-tspspi** 0.0.3 (2026-11-01, "WORK IN PROGRESS", `start_blender(background=true)`, "viewport screenshots require a GUI") **[docs]**; **sandraschi/blender-mcp** spawns `blender --background` per tool **[unverified]**. Neither beats the Lab add-on.

**Which works in a container**: Lab add-on in `--background --command blender_mcp` (no display) → yes; `bpy` wheel → yes; ahujasid → only with Xvfb + GUI and Mesa software GL **[docs/est]**.

## 2. Containerising

- **Version**: the Lab add-on forces **5.2.3 LTS** (`blender_version_min 5.1.0` rules out 4.5 LTS); both LTS lines updated 2026-10-22; 5.x bundles Python 3.13 **[docs]**. Tarballs: 5.2.3 ≈ 385 MB (prior note), 4.5.15 = 378,036,492 bytes **[docs]**. Linux needs glibc ≥ 2.28 **[docs]**.
- **Modal image** (no Dockerfile needed) **[est, from docs]**:
  ```python
  image = (modal.Image.debian_slim(python_version="3.13")
    .apt_install("libgl1","libegl1","libxkbcommon0","libxi6","libxrender1","libxfixes3",
                 "libxxf86vm1","libglib2.0-0","libgomp1","libsm6","xz-utils","curl")
    .run_commands("curl -fsSL https://download.blender.org/release/Blender5.2/blender-5.2.3-linux-x64.tar.xz | tar -xJ -C /opt && ln -s /opt/blender-5.2.3-linux-x64/blender /usr/local/bin/blender")
    .env({"NVIDIA_DRIVER_CAPABILITIES": "compute,utility,graphics"})
    .add_local_dir("vendor/blender_mcp/addon/blender_mcp_addon", "/addon", copy=True)
    .run_commands("blender -b -c extension build --source-dir /addon --output-dir /tmp",
                  "blender -b -c extension install-file /tmp/mcp-1.0.0.zip --repo=user_default")
    .uv_pip_install("httpx", "pillow"))   # + "mcp<2" only if the MCP shim is kept
  ```
  ≈ 1.3 GB installed **[est]**. The same lines make an Ubuntu Dockerfile for Fly/RunPod (`FROM nvidia/cuda:12.x-base-ubuntu22.04`). Add `xvfb` and `xvfb-run -a -s "-screen 0 1280x720x24"` only for the ahujasid route; Blender's GUI needs OpenGL 4.3 **[docs]**, which Mesa's llvmpipe provides in software (the llvmpipe page states it is a CPU rasteriser but not its GL level **[docs]**; 4.3 support **[unverified]**).
- **Engines headless**: Cycles on CUDA/OptiX with no display, as the prior note shows; Workbench renders headless and is the cheapest "shape check" (<1 s) **[est]**; EEVEE on Modal remains **[unverified]** (needs `libEGL_nvidia`, prior note). Modal's GPU guide says nothing about EGL/`NVIDIA_DRIVER_CAPABILITIES` **[docs, absence]**.
- **Modal specifics**: `gpu=` accepts T4, L4, A10, L40S, A100-40GB/80GB, RTX-PRO-6000, H100, H200, B200, B300, with ordered fallbacks `gpu=["L4","A10"]` **[docs]**. Per second: T4 0.000164, L4 0.000222, A10 0.000306, L40S 0.000542, CPU core 0.0000131, GiB 0.00000222; volumes 0.09 USD/GiB-month (1 TiB free), egress 0.04 USD/GiB; Starter 30 USD/month credit, 10 concurrent GPUs **[docs]**. Function timeout default 300 s, max 24 h; `scaledown_window` 2 s–20 min, default 60 s, idle billed **[docs]**. Web functions (`fastapi_endpoint`, `asgi_app`, `web_server(port, startup_timeout=5.0, requires_proxy_auth=False)`) cap a request at **150 s**, then 303-redirect; Modal recommends `.spawn()` + poll **[docs]**. Sandboxes (`Sandbox.create(image=, timeout≤24 h, volumes=, secrets=)`, `sb.exec`, `encrypted_ports` + `sb.tunnels()`; GPU needs `runtime="gvisor"`) suit an interactive session **[docs]**.
- **Cold start**: boot ~1 s, then imports and `@modal.enter` **[docs]**; Blender start + add-on + CUDA kernels ≈ 10–20 s **[est]**; snapshots fail after graphics use (prior note), so snapshot before the first render, if at all.
- **Alternative hosts**: RunPod serverless 24 GB tier (L4/A5000/3090) **0.75 USD/h**, 48 GB (L40S) 1.75; pods L4 0.44 community / 0.59 secure **[docs]**: ~6% under Modal's L4 serverless, under half for an always-on pod, but no Python-native `spawn`, volumes or secrets. ## 3. The agent loop

- **MCP client in Python**: v1 (`mcp<2`, what the Lab server pins): `stdio_client(StdioServerParameters(command=…, args=…))` → `ClientSession(read, write)` → `initialize()`, `list_tools()`, `call_tool(name, arguments)` → `CallToolResult(content=[TextContent|ImageContent(data, mimeType)], isError, structuredContent)` **[docs]**. v2 (`mcp` 2.3.0 on PyPI) keeps `ClientSession` and `stdio_client`, adds `Client`, raises `MCPError` instead of `isError=True`, snake_cases fields (`is_error`), swaps `httpx` for `httpx2`; v1 "keeps receiving critical bug fixes" **[docs]**. Pin `mcp<2` beside the Lab server.
- **Bridging to OpenRouter**: `POST /api/v1/chat/completions` with `tools=[{"type":"function","function":{name, description, parameters}}]`; the model returns `tool_calls`; append the assistant message and one `{"role":"tool","tool_call_id":…}` per call; `tools` must be resent every request; `parallel_tool_calls` defaults to true **[docs]**. Images: `{"type":"image_url","image_url":{"url":"data:image/png;base64,…"}}` after the text part; PNG/JPEG/WebP/GIF; several per message **[docs]**. A render comes back as tool text ("rendered /out/r3.png") plus a following user message carrying the image, since tool messages are text in the OpenAI shape **[est]**. Filter models by `supported_parameters` ∋ `tools` and `input_modalities` ∋ `image` **[docs]**. Every response carries `usage.cost` (credits = USD); `usage.include` is deprecated, "has no effect" **[docs]**. No inference markup; 5.5% fee on credit purchases **[docs]**.
- **Models with tools + vision, OpenRouter list today (285 of 460), USD per M tokens in/out** **[live]**: `anthropic/claude-haiku-5.5` 0.10/0.50 (ctx 1M); `anthropic/claude-sonnet-5.5` 2.00/10.00; `anthropic/claude-opus-5.5` 4.00/20.00; `google/gemini-3.1-flash-lite` 0.25/1.50; `google/gemini-3.8-flash` 0.825/4.125; `google/gemini-3.1-pro-preview` 2.00/12.00; `openai/gpt-5.6-luna` 0.20/1.20; `openai/gpt-5.4-mini` 0.75/4.50; `openai/gpt-5.5` 5.00/30.00; `qwen/qwen3.7-flash` 0.03/0.13; `z-ai/glm-5.3-flash` 0.034/0.083; `qwen/qwen3-vl-235b-a22b-instruct` 0.21/1.90; `x-ai/grok-4.7` 2.00/6.00. Whether a cheap model writes *correct bpy 5.2* is a different question (prior note § 1: API drift is the top failure).
- **Image tokens at ~1 MP**: Anthropic 1000×1000 = **1,296** tokens (`w×h/750`, max 1568 px long edge) **[docs]**; Gemini 1024² = 4 tiles × 258 = **1,032** **[docs]**; GPT-5.1 1024² = 70 + 4×140 = **630**, patch models (gpt-5.6/5.5/5.4, ×1.2) ≈ **1,229** **[docs]**.
- **One 8-round job** **[est]**: 16 model calls (write code → run → render → review), context growing from ~3k to ~25k tokens (8 images ≈ 10k + code/results), mean ~14k → **≈ 225k input, ≈ 8k output**, no caching. Haiku 5.5 **0.027 USD**; GPT-5.6 luna **0.055**; Gemini 3.8 Flash **0.22**; Sonnet 5.5 **0.53**; Qwen 3.7 Flash **0.008**. Prompt caching on the growing prefix would cut the input share ~4× **[est]**.
- **Skip MCP, expose plain function tools**: same LLM, same add-on socket, minus `uv`, the `blmcp` package, the stdio subprocess and the `mcp` client: four tools (`execute_bpy(code) → stdout/err + JSON`, `render(camera, w, h, samples, engine) → image`, `inspect(name?) → bbox/dims/materials`, `export_glb(opts)`), each a 10-line wrapper around the Lab add-on's code-execution request. Keeps the crash isolation of a separate Blender process. **Recommended.**
- **Claude Agent SDK / `claude -p`**: `claude --bare -p "<brief>" --mcp-config '{"mcpServers":{"blender":{"command":"blender-mcp"}}}' --allowedTools "mcp__blender__execute_blender_code,…" --output-format json --max-turns 24 --max-budget-usd 0.5` returns `total_cost_usd` (client-side estimate) **[docs]**; Python `claude-agent-sdk` has `ClaudeAgentOptions(mcp_servers, allowed_tools, max_turns, max_budget_usd)` and `ResultMessage.total_cost_usd` **[docs]**. Through OpenRouter: `ANTHROPIC_BASE_URL=https://openrouter.ai/api`, `ANTHROPIC_AUTH_TOKEN=<OpenRouter key>`, `ANTHROPIC_API_KEY=""`, `ANTHROPIC_DEFAULT_HAIKU_MODEL=…`; "only guaranteed to work with the Anthropic first-party provider" **[docs]**; Claude Code's gateway protocol is the Anthropic Messages format only **[docs]**. Claude Code's own prompt adds thousands of (cached) tokens per turn, and `render_viewport_to_path` returns a path, so the model must `Read` the PNG **[est]**. Fastest way to *try* the loop interactively; not the runtime for a pipeline step.

## 4. Shape of the service for Zumi

```
Windows pipeline (Python 3.14)                 Modal (L4, one container per job or per episode)
props.py: spend.reserve(worst) ──► BlenderJob.run.spawn(brief, panels[], budget_usd)
                                      @modal.enter: blender -b --factory-startup --command blender_mcp
                                                    --host 127.0.0.1 --port 9876   (subprocess)
                                      loop: OpenRouter chat/completions ⇄ 4 tools ⇄ add-on socket
                                      Cycles 64 spp 1200×500 on OptiX → PNG → next user message
                                      stop: approved | rounds==8 | Σ usage.cost ≥ budget_usd
                                      /vol/props/<episode>/<setting>/{set.glb, r1..r8.png, trace.json}
            ◄── result {cost_usd, rounds, glb_path} ◄── FunctionCall.get()
spend.record("openrouter", cost_usd, tag=...)   copy GLB from modal.Volume to .data/
```

- **Where**: the agent loop lives *in the container* (one network hop to Blender, none to Windows). The pipeline is already Python, so it calls `BlenderJob.run.spawn(...)` with the Modal client and polls `FunctionCall.get(timeout=0)` from its existing `paid_map` worker; no web endpoint, no 150 s cap, function `timeout=1800` **[docs/est]**.
- **One Blender per job vs warm pool**: `@app.cls(gpu="L4", scaledown_window=300, timeout=1800)` with Blender started in `@modal.enter()`; each job starts by `execute_bpy("bpy.ops.wm.read_factory_settings(use_empty=True)")` so state never leaks; one input at a time (the add-on serves one scene) **[est]**. An episode's 3–6 settings then share one cold start; the idle window costs 300 s × 0.000266 ≈ 0.08 USD at most **[est]**. Crash policy: if the Blender subprocess dies, restart it and replay the job's accepted code cells from `trace.json` **[est]**.
- **Spend guard**: `spend.py` reserves a worst case before a call and records the actual in `.data/spend/openrouter.jsonl` (`reserve` / `record`, cap `ZUMI_DAILY_USD`) **[in-house]**. The container cannot write that ledger, so the job takes `budget_usd`, sums `usage.cost` from every response, refuses the next call when the sum would pass it, and returns the sum; the pipeline wraps spawn→get in `with spend.reserve(budget_usd, f"props:{setting}")` and calls `spend.record("openrouter", result.cost_usd, setting=…, rounds=…)` inside. Haiku 5.5 worst case at 8 rounds ≈ 0.05 USD → `budget_usd=0.10` **[est]**. Modal time: add a `"modal"` ledger and record `seconds × rate` from the job's own timer **[est]**. Keep the field name `cost` for openrouter lines (`_usd` reads it) **[in-house]**.
- **Secrets**: `modal secret create openrouter OPENROUTER_API_KEY="$OPENROUTER_API_KEY"` from a shell that sourced `pipeline/.env`, or `modal.Secret.from_dotenv(path)` at deploy; attach `secrets=[modal.Secret.from_name("openrouter")]`, read `os.environ` **[docs]**. Log `usage` and tool names only; `trace.json` holds code and costs, not the key **[est]**. Run Blender with `--offline-mode` unless an asset fetch is wanted **[docs]**.

## Recommendation

1. **Lab add-on in `--background --command blender_mcp` + plain function tools + OpenRouter, on a Modal L4 Cls, called by `spawn` from the pipeline** — best quality per dollar (Haiku 5.5 ≈ 0.03 USD per 8-round job, Modal ≈ 0.05) and per engineering hour (one Python file, no Xvfb, no MCP transport, no web endpoint; ~1–2 days to the GLB in Unity) **[est]**.
2. **Same, with the MCP shim (`blender-mcp` stdio + `mcp<2` client)** only if the tool set must be shared with Claude Code for interactive debugging of the same container (`blender-mcp --transport http` behind a Modal tunnel) **[src/docs]**.
3. **Claude Code headless via OpenRouter** for the first manual sessions, not for the step.
4. **ahujasid under Xvfb** only if its asset/generative plumbing is wanted in-process; otherwise call Poly Haven/Tripo by HTTP (prior note § 2–3).

**Risks.** (a) Cheap models looping on bpy 5.2 API errors: keep the 5.2 API sheet in the system prompt, cap rounds (prior note § 1). (b) Screenshots are ~45% of input tokens: downscale to 800×500, crop to the object **[est]**. (c) EEVEE on Modal unverified; Cycles 64 spp is the plan. (d) The Lab add-on is 1.0.0 (2026-09), GPL-3, vendored: a Blender 5.3 move may change its CLI. (e) Key leakage through request logging: log tool names and `usage` only. (f) Idle cost: `scaledown_window ≤ 300`, never `min_containers`. (g) One scene per process: no `@modal.concurrent`.
