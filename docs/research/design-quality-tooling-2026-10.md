# Getting high-quality visual UI out of Claude Code (web + Quest 3) — 2026-10-17

Research date: 2026-10-17. Primary sources only where they could be reached: SKILL.md / README / reference files read through the GitHub API (`gh api -H "Accept: application/vnd.github.raw"`), GitHub API for stars / last push / licence (all figures 2026-10-17), Meta developer docs (page `last_updated` quoted), Unity package docs and forum status posts, Figma Help Center, Anthropic Claude Code docs. Vendor blogs are used only for the diagnosis section and are labelled as such. Google Stitch's docs site renders client-side and returned only a title; Stitch facts rest on Google's own GitHub repos (`google-labs-code/stitch-skills`, `google-labs-code/design.md`, `gemini-cli-extensions/stitch`). Anything else is marked **unverified**. Companion to `design-system-skills-2026-10.md` (tokens / Storybook skills), which this file does not repeat.

## Executive summary

1. **The only measured evidence that anything moves visual quality comes from `pbakaus/impeccable`'s comp-fidelity work (2026-08):** same model, same approved comp, a one-pass build scored 46-56% on a pixel/structure diff while the gated "spec → plates → hero → sections" build scored 62-77%; a human review of 32 builds (230 pinned defects) put the pass line at 68-73 [S5]. Its stated root cause is the diagnosis for Zumi too: *"every fidelity check in the build phase was the model judging its own reproduction from memory of an image... Code-led builds 'look better' only because they have no target to fail against"* [S5].
2. **Skills change behaviour in three ways, in descending evidence:** (a) a pixel target + measured comparison (impeccable comp-led path; Anthropic's own best-practice prompt "paste screenshot… take a screenshot of the result and compare… list differences and fix them" [S1]); (b) a real-browser look-and-fix loop with a rubric (taste-skill v2: 3 widths, 14 passes, fix top 3, 3 rounds [S3]; designer-skills `design-review`: mandatory Playwright screenshots at 375/768/1280 [S4]); (c) banned-tells lists and deterministic detectors (impeccable's 59 rules, taste-skill's house rules backed by a 247-site study: icon-topped feature cards 1% of strong sites vs 28% of weak, gradient fills 22% vs 52% [S3]). Retrieval skills (`ui-ux-pro-max`, 136.6K stars) add vocabulary, not a loop [S6].
3. **No external AI design tool exports to Unity.** Figma MCP, Stitch, v0, Magic Patterns, Superdesign, Onlook, 21st, Lovable, Claude Design all produce web HTML/React [S10-S19]. For Zumi they can only serve the one landing page and as *comp generators*. The pixel source that matters is the comic artist.
4. **XR: Meta's design system is numeric and uGUI-based.** UI Set = uGUI Canvas + TextMeshPro prefabs with Theme ScriptableObjects, ray + poke, backplate mandatory [S20]; panels 1024×640dp default (384×500 min, 1440×1000 max) [S22]; 48dp hit targets, 60dp primary [S23]; text ≥14px, 18px comfortable, Inter, no italics, no #000/#FFF (dark bg ≥ #1A1A1A) [S23-S25]; direct touch at 42-46 cm, indirect 0.8-3 m, 12 mm between targets, 2.5-3° angular minimum [S26]; content ~1 m away, slightly below eye line, never head-locked [S27]. Unity UI Toolkit world-space is still "pre-release" (6.2, XRI 3.2: poke + near-far only, no ray) [S30] and Meta's Interaction SDK documents no UI Toolkit path [S20, S21]. **`decisions.md` line 135 ("design system now lives in Unity UI Toolkit") should be revisited: headset panels should be uGUI/UI Set.**
5. **Recommendation:** install impeccable (hook + `critique` + `document` → DESIGN.md) and run taste-skill v2 once for the landing page; do not buy an external tool; build XR panels on Meta UI Set with a tokens→C# Theme exporter; and run a fixed per-screen loop: references + artist comp → build → detector hook → screenshot (Chrome for web, `Unity_Camera_Capture` from the user-eye camera for XR) → critique → ≤3 fix rounds → numeric done criteria (section 6d). Expect 1-3 h per screen; the comp-led path costs 2-4× the tokens of a one-pass build [S5].

### 4c. What shipped Quest UIs have in common

Primary evidence is thin; what the sources say: Meta's system UI is a backplated, rounded, gradient-tinted panel family that dims the world behind it (UI Set backplate rule [S20]; Navigator "replaced the murky gray oval with a simple dimming of the background", UploadVR 2026-06-08 [S41]). Beat Saber's menus "curve around the player against a muted dark backdrop, with large, clearly marked buttons", and the same critique warns that flat desktop menus moved into 3D read as "cramped, hard-to-read" (Medium, secondary) [S42]. Demeo's team learned that an untitled option row was skipped because players "assumed it was art" (Resolution Games blog) [S43]. No Meta "best of 2025" UI award list was found. Common traits, by inference (**not measured**): dark semi-opaque backplate, large targets, world-anchored at ~1 m, 3-5 type sizes, every control with hover/pressed/audio states, decorative art kept off the control surface.

## 5. Diagnosis: why Claude's UI reads as a wireframe

| Symptom | Mechanism (what the sources say) | Fix with evidence |
|---|---|---|
| Same layout every time (centred hero, three cards, equal boxes) | "Distributional convergence": with no decision, the model emits the training-data average (Superdesign, vendor [S8b]); impeccable: "the same handful of tells on every project" [S2]; taste study: centred statement + media below is 7% of strong sites, 24% of weak [S3] | Decide the direction *before* code (frontend-design plan step [S7]; impeccable mode + direction contract [S2]; taste `draw.mjs` deals one direction [S3]) |
| No imagery, empty ground | "Models skip pictures and footage because finding them is work; the page fails without them"; "a screen that is mostly empty ground is an underbuilt section" [S3] | Real assets first (artist art, covers, panels); comp regions that are raster get a "plate" or the build gate refuses [S5] |
| Equal weights, no hierarchy | Default treatment "a big number with a small label, supporting stats, and a gradient accent" [S7]; detectors flag line length, cramped padding, small targets [S2] | One ground / one ink / one accent (taste) [S3]; `typeset` / `layout` commands [S2] |
| Component-first, screen-second | Superdesign: layout before components — "a terracotta button on a standard hero layout still looks generic" [S8b]; impeccable: Operate screens are built, Persuade screens are pictured first [S5b] | Screen comp for Persuade surfaces (landing, lobby, end card); code-first with a contract for Operate surfaces (reader controls) |
| No look-back | Anthropic: "Claude stops when the work looks done. | Self-grading from memory | "every fidelity check… was the model judging its own reproduction from memory of an image" [S5] | Mechanical diff against the comp (comp-diff) [S5]; for Unity, side-by-side PNG of comp vs `Unity_Camera_Capture` read by a *separate* critic |
| Vague feedback ("make it premium") | Adjective loops converge again (Superdesign [S8b]); taste: "Judge only the pictures" [S3] | Critique in a fixed rubric with numbers (/40 heuristics; pin list) [S2, S5] |
| XR-specific: flat web habits in a lit room | Flat menus in 3D read cramped [S42]; Meta: no pure black/white, shadows for placement, dim content under dialogs, test on device because colours saturate [S27, S28] | Build on the UI Set backplate; place at Meta distances; one on-device check per screen |

## 6. Recommendation for Zumi

**(a) Skills, in sequence (install today, ~30 min).**
1. `npx impeccable install` → `/impeccable init` (PRODUCT.md from `docs/design/brief.md`) → `/impeccable document` to write `DESIGN.md` from `packages/design-tokens/tokens/*.tokens.json` and the brief; lint it with `npx @google/design.md lint DESIGN.md` (contrast against Meta's 4.5:1 / 3:1). Enable the post-edit detector hook. Use `critique` (/40) and `audit` after every screen, `polish` before shipping. Mode: landing = Persuade (comp-led), lobby/end card = Experience, reader controls = Operate (code-led) [S2, S5b].
2. `npx skills add https://github.com/Leonxlnx/taste-skill --skill design-taste-frontend` — run **once**, for the landing page only (its own scope excludes app screens); budget 45 min and ~300K tokens; keep its inspector screenshots as the review artefact [S3]. Its "no gradients" rule conflicts with the lamp-glow brief: the brief wins (impeccable: "The brief wins") — keep the glow as a painted asset, not CSS gradient.
3. Write `zumi-xr-ui` (own skill, 1 page): Meta numbers from section 4a as hard checks, UI Set prefab names, panel placement defaults (1 m / 1024×640dp / backplate), the screenshot protocol via `Unity_Camera_Capture`, and the done criteria below. `designer-skills design-review` is worth borrowing for its screenshot protocol only; `frontend-design` is already loaded and is impeccable's ancestor, so do not run both on the same screen.

**(b) External tool: none paid.** Nothing exports to Unity (section 2). Free options that fit: Stitch (free, MCP, DESIGN.md) for 2-3 landing-page explorations; Claude Design (in the Max plan) for quick comps. Neither replaces the artist. Figma Dev seat ($12/mo) only if the artist wants to re-theme the Meta UI Set Figma file; otherwise skip. ShapesXR free tier only if panel distance needs a headset mock-up the artist can walk around; not required in 4 weeks.

**(c) XR toolchain.** Meta XR Interaction SDK Essentials → Horizon OS UI Set prefabs (uGUI + TextMeshPro) themed via `Theme` ScriptableObjects generated from the DTCG tokens (new Style Dictionary C# format; `midnight` and `paper` themes map to two Theme assets; `UIThemeManager.ApplyTheme(int)` switches at runtime) [S20]. Curved canvas from the ISDK UI prefabs for the reader rail [S20c]. Keep UI Toolkit/USS for editor tooling and the 2D fallback only, until XRI/ISDK ray support for UI Toolkit ships [S30]. Amend `docs/architecture/decisions.md` accordingly. Fonts: Inter (Meta's recommendation) for controls; the brand condensed display face only on titles ≥ 20dp, no italics [S24, S25]. No Figma/ShapesXR step is required; the artist paints comps at 1024×640 (panel) and 1440×900 (landing).

**(d) Screen design loop (repeatable; target 1-3 h per screen).**

| Step | What | Done when |
|---|---|---|
| 0 Inputs | `brief.md`, `DESIGN.md` (from tokens), 5-10 references in `docs/design/references/` (today: 1 file; add WEBTOON/Kakao reader, Quest home, Beat Saber menu, Ghibli night frames, Deadlock page), real art (covers, panels, orb sheet) | Folder listed in the prompt; Claude names the mode and the one idea in a 5-line direction contract |
| 1 Comp | Persuade/Experience surfaces: artist comp, or `Unity_AssetGeneration_GenerateAsset GenerateImage` / Stitch from the references, at panel size; Operate surfaces: skip, contract only | One comp locked by you |
| 2 Build | Web: HTML/CSS from tokens. XR: UI Set prefabs on a backplate at 1 m, 1024×640dp, min/default/max layouts | Detector hook clean (`npx impeccable detect`, exit 0) |
| 3 Look | Web: screenshots 1440/768/390 (taste inspector or Chrome). XR: `Unity_Camera_Capture` from the user-eye camera at 1 m, dark room lighting on, plus a 384×500 and 1440×1000 pass; save PNGs under `.design/<screen>/screenshots/` | Side-by-side comp vs capture written to disk |
| 4 Critique | `/impeccable critique` (/40) in a **fresh subagent** that sees only comp + capture + DESIGN.md; XR adds the Meta checklist (48/60dp targets, 12 mm gaps, ≥14px, 4.5:1, ≥ #1A1A1A, no italics) | Written list, top 3 fixes named |
| 5 Fix | Fix top 3, re-capture, re-critique; max 3 rounds (taste's cap) | Score stops rising or ≥ 32/40 |
| 6 Device | One human look in the Quest 3 per screen (Meta: colours saturate, only hardware shows true legibility) | Note in `DESIGN_REVIEW.md` |

Done criteria: critique ≥ 32/40 (impeccable says most real interfaces score 20-32), detector exit 0, all Meta numeric checks pass, comp-diff ≥ 0.72 where a comp exists (impeccable's web-calibrated threshold; **untested on Unity captures**), device check signed off.

**Uncertainty, stated plainly.** The only quantified quality evidence is impeccable's self-run evals (n=2-3 per niche, web, GPT/Opus) [S5]; taste-skill's evidence is a correlational site study, not an A/B of its own output [S3]; nothing measures any of this on Unity UI. Stitch quotas, Figma MCP tool names, Claude Design's Claude Code handoff and ShapesXR's Unity package export are unverified. Meta's two typography pages disagree on the typeface (Inter vs Optimistic Display). UI Toolkit world-space status past 6.2 is "pre-release" with open Quest-related bugs; a 2026 change could invalidate the uGUI recommendation.
